## Keep Entities Persistence-Only and Consistent with TypeORM

The TypeORM form of `db-schema-conventions`: read that rule first for the conventions and why they hold. Entities carry only persistence decorators (`@Entity`, `@Column`, `@PrimaryGeneratedColumn`, relations, `@Index`, `@Check`), with one exception: `@Exclude()` (class-transformer) and `@ApiHideProperty()` (Swagger) **together** on columns that must stay out of both the response body and the OpenAPI schema, such as `deletedAt`. `@ApiProperty` and `@Expose` never go on entities (see `api-use-dto-serialization`).

- The table name is passed explicitly: `Order` in `order/entities/order.entity.ts` maps to `@Entity('orders')`; `OrderItem` maps to `@Entity('order_items')`.
- The required `SnakeNamingStrategy` (below) maps camelCase properties to snake_case columns. Never write column names by hand; the one exception is the foreign key below.
- Timestamps: `@CreateDateColumn({ type: 'timestamptz' })` and `@UpdateDateColumn({ type: 'timestamptz' })`.
- Soft deletes: `@DeleteDateColumn({ type: 'timestamptz', nullable: true })`, hidden with `@Exclude()` + `@ApiHideProperty()`. Delete with `softDelete()` or `softRemove()`; `delete()` and `remove()` still remove the row. `softRemove()` also soft-deletes loaded children whose relation has `cascade: ['soft-remove']`. `find*` and the query builder skip soft-deleted rows.
- Complex structured data: `@Column({ type: 'jsonb' })`, plus `nullable: true` or a `default` when the value is optional.
- Relations: `@ManyToOne` / `@OneToMany`. The owning side declares the foreign key twice, as the relation and as a plain `userId` column, and `@JoinColumn({ name: 'user_id' })` pins both to the same column. The name matches what the naming strategy generates; writing it out keeps the pairing visible and stops a second column appearing when the relation is renamed.
- Sensitive columns: `@Exclude()` + `@ApiHideProperty()`.
- `@Index`, `@Unique` and `@Check` take the `IDX_`, `UQ_` or `CHK_` name as their first argument (`@Index('IDX_orders_user_id_status', ['userId', 'status'])`). Without it, TypeORM generates a hash that changes whenever the columns do.
- **Ids are `@PrimaryGeneratedColumn('uuid')`, generated by PostgreSQL's built-in `gen_random_uuid()`** (PostgreSQL 13 and later). Every DataSource sets `uuidExtension: 'pgcrypto'`, which makes TypeORM write that default, and `installExtensions: false`, which stops it from running `CREATE EXTENSION` on its first connection. Without them, TypeORM writes `uuid_generate_v4()` and creates the `uuid-ossp` extension, which needs a privilege the app's database user should not have. TypeORM reads either function as a generated uuid, so the drift check does not catch a DataSource that leaves the options out. An extension a column really needs (`citext`) is created by hand in the migration that adds the column.
- **TypeORM matches a CHECK constraint by its name only, and never compares an index's `where`.** Changing a CHECK's expression or a partial index's condition generates nothing, and the drift check passes. Give the changed object a new name in the same change (`CHK_orders_total_cents_positive` for a new condition), so `migration:generate` drops the old one and creates the new one.
- A native enum (see `db-schema-conventions` for when) is `@Column({ type: 'enum', enum: OrderStatus, enumName: 'order_status', default: OrderStatus.Pending })`. Without `enumName`, TypeORM names the type `orders_status_enum`. A `varchar` set is `@Column({ type: 'varchar' })`, or `@Column({ type: 'varchar', array: true })` for several (a user's roles), typed with the TypeScript enum.

### `SnakeNamingStrategy` is required

Configure `SnakeNamingStrategy` (from `typeorm-naming-strategies`) on **every** `DataSource`: the one the app uses **and** the one the migration CLI uses.

- **TypeORM's default naming strategy uses the property name as the column name**, the camelCase columns `db-schema-conventions` rules out.
- **One central rule instead of per-column overrides.** Hand-written `@Column({ name: 'created_at' })` is forgotten on the next column and never applies to join columns or junction tables. The strategy names everything consistently.
- **Both DataSources must match.** If the migration DataSource uses a different strategy than the app, `migration:generate` sees every column as renamed and produces drift (see `db-typeorm-use-migrations`). The same holds for the uuid options below.

`typeorm-naming-strategies` 4.1 declares support only for TypeORM 0.2 and 0.3, and works on TypeORM 1.1: allow it with a package-manager override, never by staying on TypeORM 0.3 (see `references/project-setup.md`). If a later TypeORM breaks it, copy its `SnakeNamingStrategy`, a small subclass of TypeORM's `DefaultNamingStrategy`, into `database/utils/`, since what knows the ORM stays out of `shared/` (see `arch-shared-folder`).

**Incorrect (default naming strategy, per-column overrides):**

```typescript
// No namingStrategy: properties become camelCase columns
TypeOrmModule.forRootAsync({ /* type, host, port... */ useFactory: () => ({ type: 'postgres', autoLoadEntities: true }) });

// Generated DDL:  CREATE TABLE "orders" ("id" uuid, "userId" uuid, "createdAt" timestamptz, ...)
// Raw SQL now has to quote every column:
await dataSource.query('SELECT id FROM orders WHERE userId = $1', [userId]);
// ERROR: column "userid" does not exist  (unquoted name folded to lower case)

// Per-column overrides: inconsistent, and forgotten on the next column
@Column({ name: 'created_at' })
createdAt: Date;

@Column()
updatedAt: Date; // Still "updatedAt"
```

**Correct (snake_case everywhere, through one strategy on every DataSource):**

```typescript
// database/database.module.ts
TypeOrmModule.forRootAsync({
  inject: [dbConfig.KEY],
  useFactory: (dbSettings: ConfigType<typeof dbConfig>) => ({
    type: 'postgres',
    host: dbSettings.host,
    port: dbSettings.port,
    username: dbSettings.username,
    password: dbSettings.password,
    database: dbSettings.name,
    schema: dbSettings.schema,
    extra: { options: `-c search_path=${dbSettings.schema},public` },
    ssl: dbSettings.ssl ? { ca: dbSettings.sslCa } : false,
    autoLoadEntities: true,
    namingStrategy: new SnakeNamingStrategy(),
    logging: dbSettings.logging,
    logger: new LoggerTypeOrmQueryLogger(),
    // gen_random_uuid(), built into PostgreSQL 13+
    uuidExtension: 'pgcrypto',
    installExtensions: false,
    synchronize: false,
  }),
});

// migrations/type-orm/config.ts
if (existsSync('.env')) {
  process.loadEnvFile('.env');
}

const schema = process.env.DB_SCHEMA || 'public';
const ca = process.env.DB_SSL_CA_FILE ? readFileSync(process.env.DB_SSL_CA_FILE, 'utf8') : undefined;

export default new DataSource({
  type: 'postgres',
  host: process.env.DB_HOST || 'localhost',
  port: parseInt(process.env.DB_PORT || '5432', 10),
  username: process.env.DB_USERNAME || '',
  password: process.env.DB_PASSWORD || '',
  database: process.env.DB_NAME || '',
  schema,
  extra: { options: `-c search_path=${schema},public` },
  // Without ca, Node's own list of CAs; the certificate is checked either way
  ssl: process.env.DB_SSL === 'true' ? { ca } : false,
  entities: [join(__dirname, '../../src/**/*.entity.js')],
  migrations: [join(__dirname, '../*.js')],
  migrationsTransactionMode: 'each',
  namingStrategy: new SnakeNamingStrategy(),
  uuidExtension: 'pgcrypto',
  installExtensions: false,
});
```

The app DataSource in `database/database.module.ts` sets the same `search_path` as the migration DataSource, sends its queries through pino without their values (`LoggerTypeOrmQueryLogger`, see `devops-use-logging`), and hardcodes `synchronize: false`, never reading it from config (see `db-typeorm-use-migrations`).

The migration CLI's DataSource in `migrations/type-orm/config.ts` uses the same strategy, and the same uuid options as the app's, or the two would generate ids differently. It runs each migration in its own transaction (`migrationsTransactionMode: 'each'`, see `db-typeorm-use-migrations`). It runs outside Nest, so it is one of the exceptions to reading `process.env` only in `src/config/` (see `devops-use-config-module`), with the same `DB_*` variables and defaults, and it loads `.env` itself. With `DB_SSL` on, it connects with TLS and checks the server's certificate, against the CA in `DB_SSL_CA_FILE` when one is set, as the app's DataSource does: this connection carries the schema owner's password. Under Jest, a database-tier spec that imports it does not see what `process.loadEnvFile()` loads, so the tier's setup file parses `.env` first (see `references/test-runner-jest.md`). The CLI runs its compiled copy, so the globs name compiled files next to it (see `references/project-setup.md`).

The generated DDL is then `CREATE TABLE "orders" ("id" uuid, "user_id" uuid, "created_at" timestamptz, ...)`, and raw SQL needs no quoting:

```typescript
await dataSource.query('SELECT id FROM orders WHERE user_id = $1', [userId]);
```

**Incorrect (API concerns on the entity, inconsistent columns):**

```typescript
@Entity()                                         // Table name left to the class name
export class Order {
  @ApiProperty({ example: '00000000-0000-0000-0000-000000000000' }) // Swagger on an entity
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Expose()                                       // Serialization opt-in on an entity
  @Column({ name: 'order_status' })               // Hand-written column name
  status: OrderStatus;

  @CreateDateColumn()                             // timestamp without time zone
  created_at: Date;                               // snake_case property

  @DeleteDateColumn()
  deletedAt: Date;                                // Soft-delete timestamp leaks into responses

  @ManyToOne(() => User)
  user: User;                                     // Implicit foreign key name
}
```

**Correct (persistence-only, uniform columns):**

```typescript
// order/entities/order.entity.ts
@Entity('orders')
@Index('IDX_orders_user_id_status', ['userId', 'status'])
@Index('IDX_orders_user_id_active', ['userId'], { where: 'deleted_at IS NULL' })
@Check('CHK_orders_total_cents_non_negative', '"total_cents" >= 0')
export class Order {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @ManyToOne(() => User)
  @JoinColumn({ name: 'user_id' })
  user: User;

  @Column({ type: 'uuid' })
  userId: string;

  @Column({ type: 'enum', enum: OrderStatus, enumName: 'order_status', default: OrderStatus.Pending })
  status: OrderStatus;

  @Column({ type: 'integer' })
  totalCents: number;

  // ISO 4217
  @Column({ type: 'char', length: 3 })
  currency: string;

  @Column({ type: 'jsonb' })
  shippingAddress: OrderAddress;

  @OneToMany(() => OrderItem, (item) => item.order)
  items: OrderItem[];

  @CreateDateColumn({ type: 'timestamptz' })
  createdAt: Date;

  @UpdateDateColumn({ type: 'timestamptz' })
  updatedAt: Date;

  @ApiHideProperty()
  @Exclude()
  @DeleteDateColumn({ type: 'timestamptz', nullable: true })
  deletedAt: Date | null;
}
```
